# Yalla - notes for developers and AI agents

Yalla (يلا) is a party game for friends and family. Players take turns naming three things in a category before time runs out, and the player picks the answer time for each round. Arabic first, English also supported.

Studio-wide rules (Jira, releases, listings, the kit, branches) come from the
org rules and the Majoon plugin (`GeeksJo/majoon-claude`): skills `do-ticket`,
`tester-build`, `release`, `jira`. This file holds only what is true for
this app.

## Run and test

- `flutter pub get`, then `flutter run`.
- Before every commit: `flutter analyze` and `flutter test`.
- No `.env` and no code generation. Localisation files in `lib/l10n/` are generated by Flutter from the `.arb` files (`l10n.yaml`) during `pub get`/build.
- Firebase config files (`google-services.json`, `GoogleService-Info.plist`) are committed. See `docs/FIREBASE_SETUP.md`.
- Release signing needs `android/key.properties` (ignored by git).
- Tests are in `test/` (services, providers, widgets).

## How the code is laid out

- `lib/main.dart`: startup order is Firebase, Analytics and Crashlytics, storage, game kit, question bank, then the providers.
- `lib/app.dart`: the app widget, routes, theme and lifecycle hooks.
- `lib/providers/`: state with `provider`. `game_provider` (match flow), `coin_provider` (coins), `game_settings_provider`, `locale_provider`.
- `lib/models/` and `lib/data/questions.dart`: game models and the question bank. Questions and categories load from `assets/content/`.
- `lib/screens/`: one file per screen (home, player setup, categories, question, pass, scoreboard, settings, how to play).
- `lib/services/`: Firebase and Remote Config (`firebase_service.dart`), kit setup (`game_kit_bootstrap.dart`), store product ids (`game_kit_products.dart`), analytics, rating, storage, the force-update and app-moved gate (`emergency_gate.dart`).
- `lib/const/remote_config_keys.dart`: every Remote Config key name.
- `lib/core/config/level_play_ids.dart`: compiled LevelPlay ids (public identifiers, not secrets).
- `lib/widgets/`, `lib/theme/`, `lib/l10n/`: shared widgets, theme, translations.

## Game kit

- Uses `GeeksJo/gameKit_package_flutter` by git ref (see `pubspec.yaml`, a tag ref). Ads, Firebase, purchases, rating, the tracking prompt, force update, notifications and the settings body come from it: change them in the kit, not here.
- The kit is set up in `lib/services/game_kit_bootstrap.dart` (`initializeGameKit`), called from `lib/main.dart`.
- The app keeps its own default Firebase app. `FirebaseService` reads Remote Config for the kit through `YallaRemoteConfigAdapter`. The kit's own named Firebase app is only used for its Remote Config.
- Own Remote Config keys (names in `lib/const/remote_config_keys.dart`): `ads_enabled`, `interstitial_cooldown_seconds`, LevelPlay app keys and unit ids per platform, force update (`min_required_version_android`, `min_required_version_ios`, store urls) and app moved (`show_app_moved`, `new_*_store_url`). Compiled defaults are in `FirebaseService` and `level_play_ids.dart`.
- Interstitial every 2 completed rounds, LevelPlay production ids always (no test ids in debug).
- Own settings look (`buildYallaGameKitSettingsUiConfig`), share text, reminder days (Mon, Wed, Fri at 18:00) and the four store products in `game_kit_products.dart` (remove ads and three donations).
- Force update: read the per-store keys in the Firebase console before relying on it; do not assume they are set.

## Rules for this app

- Rewarded ads (free coins) exist in the code but the player cannot reach them: no category in `assets/content/categories.json` is `lockedByDefault`, and the offer lives in `LockedCategorySheet` (YAL-21).
- Raise a force-update key only after that version is live on that store (comment in `remote_config_keys.dart`).
- Start Firebase before the kit: the ads kill switch is read from Remote Config while the kit config is built (`main.dart`).
- Debug builds turn Analytics collection off (`main.dart`). Do not turn it on for debug.
- LevelPlay ids are frozen at launch (`freezeLevelPlayPlacements`). A Remote Config change applies on the next launch.
- Fastlane and CI are not used for now. Builds are made by hand (`android/fastlane/` is only a template).
